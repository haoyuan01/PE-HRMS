# v1.2 — show_all list scoping, leave month filter, empty Staff List fix

**Version:** v1.2
**Date:** 2026-11-03
**Branch:** `developement`
**Commits:** `32610b6` (leave), `3fbb656` (dashboard), `f1e2429` (claims)
**Type:** Feature, bug fix

---

## Summary

The backend now decides which records belong in "My" and "Staff/Recent"
lists from the token and a single `show_all` flag. The Leave Requests page,
the Expenses Claim page and the dashboard's leave and claim tables were
switched over to it. The Leave Requests page also gained a month/year filter,
and two pages that showed an empty Staff List when opened from the dashboard
were fixed.

## API changes

`show_all=1` = Staff List / Recent, `show_all=0` = My List / My.

| Endpoint                              | Before                                                        | After                                                        |
| ------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------ |
| `GET /leave-requests`                 | `page`, `user_uuid` / `manager_approver_uuid` / `is_director` | `page`, `size=15`, `show_all`, `month_year`                  |
| `GET /leave-requests/status-summaries`| no params                                                     | `show_all`, `month_year`                                     |
| `GET /claim-headers`                  | `page`, `user_uuid` / `manager_approver_uuid` / `is_director`, `name`, sort | `page`, `show_all`, `name`, sort (Staff List only) |
| `GET /dashboards/leave-requests`      | `relevant_to_me=1` (My) / none (Recent)                       | `show_all=0` (My) / `show_all=1` (Recent)                    |
| `GET /dashboards/claim-headers`       | `relevant_to_me=1` (My) / none (Recent)                       | `show_all=0` (My) / `show_all=1` (Recent)                    |

- `month_year` is `MM-YYYY` (e.g. `03-2026`). It is **omitted** from the
  query when no month is selected; the backend treats a missing value as
  "all months".
- On `/claim-headers`, `page`, `name` (search box) and
  `sortBy=created_at&orderBy=desc` were kept: dropping them would break
  paging, search and newest-first order.
- The client-side "hide my own requests/claims from the Staff List" filters
  were removed on all three surfaces. They ran after the server had picked its
  page, so pages could show fewer than 15 rows and the footer total counted
  rows that were hidden (against `PAGINATION.md`). Each list now shows exactly
  what the backend returns.
- Export (`/leave-requests/export-excel`) still uses `relevant_to_me`;
  unchanged.

## Leave Requests: month/year filter

- **Filters** button beside the My List / Staff List tabs opens
  `leave-filter-modal.tsx` (Month + Year selects, Cancel / Apply). Follows the
  standard filter pattern: apply on Apply, a chip such as "March 2026", and a
  red Reset.
- The API needs month and year together: picking a month with no year fills
  in the current year, and Apply is disabled with a message if only one is
  set.
- Applying or resetting returns to page 1. The filter persists across tabs.
- No search box: the endpoint doesn't support search.
- The status cards (`useLeaveStatusSummary`) refetch on tab and filter
  changes with the same `show_all` / `month_year`, so they match the table.
  Responses are keyed by tab + month, so a late reply is ignored.

## Bug: empty Staff List after "View more" on the dashboard

**Symptom:** Clicking **View more** on Recent Leave Request or Recent Claim
Request opened the page on the Staff List tab with an empty table, while the
leave status cards showed the right totals.

**Cause:** The page renders on My List first, then an effect reads
`?tab=staff` and switches. With React's dev double-mount this fires
My → Staff → My requests. The list hooks had no stale-response guard, so when
the last My List reply (0 rows for a user with no own requests) arrived after
the Staff List reply (6 rows), it overwrote the table. The cards already
ignored stale replies, which is why they stayed correct.

**Evidence (temporary proxy log, since removed):**

```
leave-requests?page=1&size=15&show_all=0  → rows=0 total=0
leave-requests?page=1&size=15&show_all=1  → rows=6 total=6
status-summaries?show_all=1               → total=6 approved=6
```

**Fix:** `useLeaveRequests` and `useClaimHeaders` number each fetch and only
let the latest one update state (rows, pagination, error, loading).

## Notes

- Recent tables on the dashboard are still only fetched and shown for the
  same roles as before (leave: managers/directors; claims:
  accountants/directors).
- Leave status cards are still managers/directors only. The API can now
  return My List totals, so they could be shown to all staff if wanted.
- Leave type dropdown on the create form still requests
  `/leave-policies?size=100`; anything past 100 policies would be dropped.
